# Tactical goals

## Preserve the existing interaction surface

Projection-kernel recovery, the row-selection grammar, dense state/structure cues, and initial board-scale quick-move/review work are established package history. Do not restart those efforts as if no implementation exists. Use the actual source and regression suite to protect them.

## TG1 — Close the reproduced boundary failures

Resolve the expanded replay's startup-close and global-publication cases; pending tab ownership across script evaluations; native EA staging and late fallback writes; delayed API readiness and monotonic snapshots; and ordinary/frame editor refresh behavior. Each fix needs its own observable BDD scenario, genuine failing test, and implementation in the existing owner.

The [closeout](2026-09-07-layer-manager-closeout.md#remaining-blockers) names the failures and candidate provenance. Thirteen failing tests are thirteen failing scenarios, not necessarily thirteen independent root causes.

## TG2 — Establish reproducible release evidence

Integrate the accepted fixes without overwriting published work. Verify the dependency lock, unchanged package checks, regenerated script, explicit-target deployment, real-host matrix, and external documentation/direction gates. Publish one truthful closeout and remove temporary verification infrastructure when no longer needed.

## TG3 — Resume board-scale product work

After correctness/evidence closeout, select one improvement to organization or review. Preserve canonical structural targeting under filters and mixed selection. A selection/group preview may be considered as a focused product slice; per-row rendering systems and speculative presenter-note metadata remain out of scope.

## Acceptance bar for every slice

An action must expose applied/rejected outcomes; durable settings must not silently diverge from the visible state; filtered rows must not override canonical structure; and runtime work must remain bounded. Follow the [outcome contract](sidepanel-outcome-bearing-state-transition-contract.md) and record failures as carefully as successes.

These priorities describe repository implementation needs. Historical AK IDs in dated documents are not current task-state evidence.
